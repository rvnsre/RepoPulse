You are an expert software engineer, HCI/accessibility specialist, security reviewer, and research-software product engineer working on RepoPulse (GitHub RSS+) v13.x.

Repository:
https://github.com/rvnsre/RepoPulse

MISSION

Improve RepoPulse without changing its core purpose: a privacy-respecting desktop discovery island for GitHub repositories.

Make it genuinely useful to:
- software engineers,
- electrical, mechanical and civil engineers,
- clinicians and biomedical researchers,
- professors and teachers,
- students,
- scientists and research software users.

Do not turn RepoPulse into an EHR, clinical decision-support system, generic paper manager, or social network.

NON-NEGOTIABLE PROCESS

1. AUDIT BEFORE EDITING
   - Pull current main.
   - Record exact commit SHA and package version.
   - Inspect:
     - README.md
     - package.json / package-lock.json
     - app/
     - src/
     - scripts/
     - test/
     - .github/workflows/
     - current GitHub release configuration
     - open issues and recent merged PRs
   - Do not assume PR #14 is correct merely because CI passed.

2. REPRODUCE BEFORE FIXING
   For every suspected defect:
   - reproduce it,
   - document expected vs actual behavior,
   - add or extend a regression test where practical,
   - then implement the fix.

3. SMALL PRS
   Split work into small, reviewable PRs:
   - data/catalog correctness,
   - rotation/accessibility,
   - README/release consistency,
   - security/release hardening,
   - professional/research discovery,
   - scholarly metadata adapters.
   Do not mix unrelated refactors.

4. NO FAKE DATA
   Never fabricate:
   - repository inventory,
   - GitHub stars,
   - “1000+ left”,
   - queue counts,
   - DOI metadata,
   - citations,
   - licenses,
   - security status,
   - regulatory approval,
   - clinical validation,
   - release status.

   Every displayed count must be computed from real state.

   Required invariant:
   displayed_remaining <= verified_eligible_unseen_count

5. GITHUB SEARCH CORRECTNESS
   GitHub Search can expose at most 1,000 results per search query.
   If collecting a larger catalog:
   - shard deterministically using non-overlapping ranges
     (stars, created/updated date, language, topic where appropriate),
   - paginate correctly,
   - deduplicate by immutable GitHub repository ID,
   - detect incomplete_results,
   - respect rate-limit headers,
   - use bounded retries and exponential backoff,
   - persist resumable collection state,
   - store collection provenance,
   - test boundary overlap/gap conditions.

   Keep these concepts separate:
   - MAX_CATALOG / capacity,
   - collected inventory,
   - eligible inventory,
   - unseen inventory,
   - displayed queue remaining.

6. VERIFY THE V13 STAR-SETTING REGRESSION
   On the audited v13 tree, app/ultimate.js had a Minimum Stars selector with:
   5K, 10K, 25K, 50K, ...
   while v13 could store/use a 20K default.

   Confirm whether this is still true on current main.

   If present:
   - add a 20K option,
   - test fresh installs,
   - test v12.x -> v13.x migration,
   - test changing away from and back to 20K,
   - make reset behavior unambiguous.

7. AUTO-ROTATION / HCI

   Treat rotating repository cards as auto-updating content.

   Default for NEW installs:
   - automatic rotation OFF.

   Modes:
   - Manual
   - 10 seconds
   - 15 seconds
   - 30 seconds
   - Custom
   - optional “Fast scan / 5 seconds”

   Requirements:
   - persistent Start/Pause control,
   - keyboard accessible,
   - placed before rotating content in logical focus order,
   - explicit accessible name that reflects the action,
   - entering a repository card with keyboard focus stops automatic rotation,
   - do NOT silently restart when focus leaves,
   - resume only after explicit user action,
   - hover may pause the hovered card,
   - hover must never be the only pause mechanism,
   - manual Next must still work immediately,
   - manual Next resets timers only if auto-rotation is enabled,
   - hidden window, editing, workspace, focus session and pending operations must block swaps,
   - no card may be automatically replaced while it or a descendant owns keyboard focus.

8. SCREEN READER BEHAVIOR

   Do not announce every automatic repository replacement using aria-live.

   For automatic rotation:
   - updates should be silent to live regions.

   For manual Next:
   - announce a concise status such as:
     “4 new repositories shown. 327 eligible repositories remain.”

   Preserve focus.
   Never move the user to a new repository because of an automatic replacement.

9. REDUCED MOTION

   If prefers-reduced-motion is active:
   - start with auto-rotation paused/off,
   - remove non-essential transform, blur and scale animations,
   - retain state changes without motion.

   Existing motion may use:
   cubic-bezier(0.22, 1, 0.36, 1)
   when motion is allowed.

10. VISUAL / ERGONOMIC QUALITY

   Preserve the current clean 2x2 discovery surface.

   Improve:
   - Next button effective pointer target toward >=44x44 CSS px,
   - visible keyboard focus,
   - high-contrast / forced-colors support,
   - text scaling,
   - no layout shift during replacement,
   - avatar preloading and cancellation,
   - image fallback without flicker,
   - clear loading/offline/error states.

11. PROFESSIONAL / RESEARCH MODE

   Do NOT rank only by stars.

   Add an optional transparent multi-signal ranking model using evidence such as:
   - repository relevance,
   - maintenance recency,
   - release cadence,
   - license presence,
   - security policy,
   - security advisories,
   - CI/build evidence,
   - documentation,
   - CITATION.cff,
   - DOI/archive links,
   - reproducibility artifacts,
   - domain relevance,
   - stars as ONE popularity signal.

   Never expose a black-box “scientific quality score”
   or “clinical trust score”.

   Instead show evidence components and uncertainty.

16. MEDICAL SAFETY

   RepoPulse is a discovery tool, not clinical decision support.

   Add a clear medical-domain notice:
   - GitHub popularity is not scientific validity.
   - RepoPulse ranking is not clinical validation.
   - Repository presence does not imply regulatory clearance.

   - accept patient identifiers as ranking input,
   - ingest/store PHI,
   - diagnose,
   - recommend treatment,

   - claim FDA/CE approval without an authoritative verified source.
